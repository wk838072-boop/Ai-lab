## Overview

This lab moves from tokenization and a TF-IDF FAQ chatbot (Task 1), to chunking documents with source offsets (Task 2), to evaluating a document retrieval chatbot with word windows and sentence-aware packing (Task 3).

## Files

| File | Purpose |
|---|---|
| `corpus.py` | Synthetic five-document corpus (fictional Northfield Institute), labelled queries and gold evidence phrases |
| `task1_tokens.py` | Whitespace splitting vs Unicode word-like regex on six inputs, optional model tokenizer, normalization risk demo |
| `faq_demo.py` | Stand-in TF-IDF FAQ bot (exact answer, suggestion, empty/unsupported input). Not the lab's `guided_chatbot.py` |
| `task2_chunks.py` | 40-word windows (overlap 0 and 10), sentence-aware packing, offsets and IDs, edge-case tests, TF-IDF suggestions |
| `task3_retrieval.py` | Strategy x backend evaluation (Hit@3, MRR@3, chunk count, times), rejection-cutoff calibration, CSV log, interactive chatbot (`--chat`) |
| `retrieval_log.csv` | Top-three chunks, scores and offsets for every query (generated by `task3_retrieval.py`) |
| `NLP_Lab_Report_M_Waqar.docx` | Full lab report |

## How to Run

Requires Python 3 and scikit-learn.

```
pip install scikit-learn
python task1_tokens.py
python faq_demo.py
python task2_chunks.py
python task3_retrieval.py
python task3_retrieval.py --chat
```

For the embedding backend, the model tokenizer and the token-length audit, also install:

```
pip install sentence-transformers transformers
```

`task3_retrieval.py` detects `sentence-transformers` automatically and adds the embedding backend, measuring model load time separately. The model name is set by `MODEL_NAME` at the top of the file; change it to the model your lab uses.

## Conventions

- A retrieval is a hit if one of the top three chunks contains the labelled gold evidence phrase. MRR@3 uses the rank of the first such chunk.
- Four answerable queries are used for development and four are held out for final testing. Two unanswerable queries belong to each split.
- The strategy is chosen on development results only. The rejection cutoff is calibrated on development examples only and is not reused as a universal cosine value.
- The chatbot never asserts an answer automatically: it shows candidate chunks with ID, document, character offsets and score, and shows the text as evidence only after the user confirms.

## Results (TF-IDF only)

| Strategy | Chunks | Hit@3 (dev) | MRR@3 (dev) |
|---|---|---|---|
| Word window, overlap 0 | 21 | 1.00 | 0.88 |
| Word window, overlap 10 | 25 | 1.00 | 0.88 |
| Sentence-aware packing | 25 | 0.75 | 0.75 |

Chosen on development results: window overlap 0. Held-out test result for this choice: Hit@3 0.75, MRR@3 0.75.

Embedding results are not included here; run `task3_retrieval.py` with `sentence-transformers` installed to add them.

## Limitations

The corpus is small and synthetic, so one query changes Hit@3 by 0.25. The rejection cutoff is based on two unanswerable development queries and rejected only one of two unanswerable test queries. `faq_demo.py` is a stand-in for the lab's `guided_chatbot.py`, and the chatbot loop in `task3_retrieval.py` should be merged into `document_chatbot.py`.
